# 01 Scope and non-negotiable rules

-   Keep the current visual identity, technical writing tone,
    engineering demo/calculator, existing useful articles, selected
    projects, working process, and engagement model. Improve content and
    navigation incrementally.

-   Do not place geographic targeting, ideal client lists, country
    flags, "based in Bangladesh," or location-based marketing on public
    marketing pages. Keep any legally required registered
    address/company details in appropriate legal/contract documents.

-   BuildIoT Lab sells remotely deliverable engineering work: designs,
    source files, integrations, documentation, advisory and remote
    testing assistance. Do not advertise overseas installation, physical
    product distribution, mass PCB manufacture or assembly as standard
    services.

-   Every claimed result, client testimonial, staff credential,
    certification, technology qualification and case-study image must be
    genuine and approved for publication. No fabricated metrics, logos,
    customer names or "live" feeds.

-   Changes should be mobile-first, accessible, fast, secure, and
    consistent across all pages.

# 08 Trust, evidence and editorial rules

-   Case study template: Summary → Challenge → Scope actually completed
    → Architecture → Evidence / test setup → Results / limitations →
    Deliverables → Project status.

-   "Demo," "internal R&D," "reference design," "client work" and
    "field-tested" must be separate and accurate labels. Get written
    permission before publishing client details or identifiable
    proprietary material.

-   For numerical claims, add device revision, setup, conditions, sample
    count, methods, date and applicable limitations; otherwise remove
    the number until verified.

-   Use real schematic screenshots, PCB renders, source excerpts, GitHub
    repositories and photographs only if authorized and redacted
    appropriately.

-   Do not imply certifications (ISO/IEC, CE/FCC, cybersecurity),
    military-grade security, guaranteed battery life or mass-scale node
    performance without supporting evidence.

-   Create an About section with actual team members or defensible team
    qualifications rather than anonymous stock photos or unverified
    "expert" claims.

# 09 SEO, accessibility, reliability and deployment

-   Use single canonical domain https://buildiotlabs.com; decide whether
    the GitHub Pages URL remains a preview or is redirected/noindexed.
    Preserve old valuable page routes with 301 redirects where
    technically possible.

-   Apply brand everywhere: visible UI, document title, meta
    description, Open Graph, favicon/title, organization JSON-LD,
    contact links, transactional templates and email sender.

-   Suggested homepage title: "BuildIoT Lab \| Engineering Ideas Into
    Reality". Suggested description: "From Circuit to Cloud --- custom
    PCB design, embedded firmware, IoT hardware R&D, cloud platforms and
    connected software engineering." Keep service keywords prominent in
    on-page H1/H2 and metadata where natural.

-   Ensure one descriptive H1 per page, clean H2 hierarchy, descriptive
    link labels, image alt text, proper form labels, keyboard navigation
    and adequate contrast.

-   Responsive QA at 320px, 375px, 768px, 1024px and desktop; no
    horizontal scrolling or overlapping technical graphics. Respect
    reduced-motion preferences.

-   Performance: compress images, lazy-load below-fold media, avoid
    unnecessary animation bundles; measure Lighthouse/Core Web Vitals
    rather than claim arbitrary scores.

-   Security: HTTPS, protected secrets, form abuse controls, privacy
    notice and cookie consent only where applicable; verify a legitimate
    receiving inbox.

-   Analytics: track CTA clicks, qualified form submissions and errors
    without recording confidential project brief content.
